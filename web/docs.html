Using cicoria

cicoria runs coding agents in terminal panes and shows, around the one on screen, its sessions, files and changes. This page covers everything it does.

cicoria is an interface for you, working with several coding agent sessions at once. It does not orchestrate agents, run workflows between them or keep them running without you: every message an agent gets is one you write or queue, agents never contact each other on their own, and they stop when cicoria closes.

Install

curl -fsSL https://henomis.github.io/cicoria/install.sh | sh

The script downloads the latest release for your system (Linux and macOS, x86_64 and arm64), checks it against the checksums of the release and puts cicoria in ~/.local/bin. CICORIA_INSTALL_DIR names another directory and CICORIA_VERSION another release, such as v0.0.4. Running it again updates cicoria.

You can also download the archive from the releases yourself and put the cicoria in it on your PATH, or build it with Go:

go install github.com/henomis/cicoria@latest

You need:

  • Go 1.26 or later, only to build it.
  • git, for the changes panel and the diffs.
  • The agents you want to run. Claude Code (claude) is the default; GitHub Copilot CLI (copilot) and Codex CLI (codex) are known too.
  • A Unix-like system. cicoria is developed and tested on Linux. Desktop notifications use notify-send, or osascript on macOS, and are skipped where neither is there.

On Windows cicoria runs in WSL2, with the archive for Linux. Install it, git and the agents inside the distribution, and keep the project in its file system rather than under /mnt/c, where git is slow. o opens a file with its Windows program. Desktop notifications need notify-send and a notification service in the distribution, and are skipped without them.

Open a workspace

cicoria            # on the current directory
cicoria ~/src/app  # or on another one
cicoria -config ./my.toml ~/src/app
cicoria -version   # which version this is

The directory you open is the workspace: its sessions are saved under it and come back the next time. The first time, one session starts with the default agent.

Everything you type goes to the agent on screen. To talk to cicoria instead, press the prefix key, ctrl+a, and then a command key. The mouse works too: click a panel or a session, scroll with the wheel, and clicks inside the agent pane go to the agent.

The title of the agent pane names the session, its agent, its status, its directory and the git branch that directory is on, or the commit when it is on no branch. It follows a branch the agent switches to. When the pane is narrow, a long branch name is cut in the middle and the directory keeps its end.

The mouse wheel and pgup/pgdn scroll back through what has left the agent's screen, and the title of the pane says how many lines back you are; typing goes back to the end. An agent that reads the mouse itself, or takes the whole screen as an editor does, gets the wheel and the keys instead.

Sessions

A session is one agent working in one directory. ctrl+a c creates one and asks three things:

  • The agent, when more than one is configured.
  • The directory it works in, starting from the one of the session on screen. tab completes, ctrl+w deletes a path component, ctrl+u clears, and ~ and relative paths work.
  • A name. A free one, such as claude-2, is offered; enter accepts it.

Closing a session whose agent is still running, or that has queued messages, asks first. Quitting asks when a Claude Code, Copilot CLI or Codex CLI session is still working.

A worktree of its own

The files and changes panels show the project of the session on screen, so two sessions in one git work tree cannot be told apart by their changes, and their agents write over each other. When you create a session where another one already works, cicoria asks whether to give it a git worktree of its own: y makes one, n or enter puts the session in the same directory and warns you, esc gives up. A shell is a way to run a command without leaving cicoria, not a session at work: it is not asked, opens in the directory you give it, and is no reason to offer the next session a worktree.

The worktree is named after the session: for a session fix-login on ~/src/app it is ~/src/app.worktrees/fix-login, on a new branch cicoria/fix-login that starts from the commit the directory was on. In the name, anything but letters, digits, - and _ becomes -. The session works there from then on, and comes back there after a restart.

Closing the session offers to remove the worktree. Its branch is always kept, so what was committed is not lost, and a worktree with changes that are not committed is kept too: the status bar says where it is. Merging the branch is up to you, or to an agent you ask.

A worktree holds what git tracks: files that are not committed or that git ignores, such as .env or node_modules, are not copied to it. Claude Code asks whether it can trust the new folder, as it does for any.

Two sessions on screen

ctrl+a - splits the agent pane in two: the session on screen stays above, and the one you pick is shown below it. ctrl+a tab, or a click in the other pane, moves the keys from one to the other. The pane that has them is the one with the lit border, and the side panels show its project.

Going to a session (ctrl+a n, p, 1 to 9) puts it in the pane that has the keys, or moves the keys when it is already in the other one. The wheel scrolls the pane it is over.

ctrl+a - again goes back to one pane, as does closing one of the two sessions. A terminal too short for two panes keeps one, and the split is not remembered across restarts.

Status

Each session carries a mark in the list, and its row shows for how long it has been so once that is a minute or more.

MarkMeaning
●Working
▲Needs input: the agent asks a question or a permission
✓Finished its turn while you were looking elsewhere
○Idle
✕The agent's process has exited and the session was kept; ctrl+a r restarts it
◌Starting

A session that needs input and is not on screen is also named in the status bar, and raises a desktop notification when notify is on.

Claude Code, Copilot CLI and Codex CLI tell cicoria what they are doing. When one says it is working but has shown no sign of life for 30 seconds, its status reads working? and its mark is dimmed. This happens after you interrupt a turn, and with Copilot CLI when a turn ends on an error. For other agents the status is guessed: output means working, quiet means idle, the terminal bell means it needs input.

A session closes when its agent or shell exits. It is kept, marked ✕, when the agent exits within three seconds of starting, so that its error can be read, when it has queued messages, and when a file, the palette or a question is open at that moment. close_on_exit = false in the settings keeps every session.

Side panels

Sessions and files are on the left, changes and the queue on the right. In a panel, j and k move, tab goes to the next panel, and esc gives the keys back to the agent.

PanelKeys
Sessionsenter go to the session, x close it, c new session
Filesenter open, h l close and open a folder, d diff, e editor, o open with the system, @ mention the file to the agent, i show or hide what git ignores
Changesenter diff, v the file, e editor, o open with the system, @ mention, s uncommitted only or since the session started
QueueSee Queue

In the file tree, folders are blue, files Claude Code, Copilot CLI or Codex CLI has edited in this run are highlighted, and changed files carry git's letter at the right. What git ignores is listed in grey, and an ignored folder is read when you open it; i in the files panel hides those files and shows them again.

ctrl+a [ and ] hide one side, b both. A terminal too narrow for the agent and the panels you asked for shows the agent alone.

Review changes

The changes panel shows what is not committed. It can also show the changes of the session: everything that differs from the commit its work tree was on when the session was created, committed or not. Work the agent commits then stays in the panel, and the title says how many commits were made since.

  • s in the changes panel switches between the two.
  • ctrl+a h starts the count of the session again from the last commit, for when you have looked at everything so far.
  • changes = "session" in the settings opens sessions on their own changes.

Outside a git repository the panel says so and the file tree lists the directory as it is.

A Markdown file opened from the file tree or by its name is shown as the document it describes: headings, lists, tables and coloured code, wrapped to the screen. m shows its text instead, at the same place, and the choice holds for the files opened after it. Notes are written on the text, and the document marks the passages that have one. A file opened from the changes panel, or next to its diff, is always text.

Notes

A note is a remark on one or more lines of a file or a diff. In the full-screen view:

  • Move to a line and press c to write a note on it. To cover several lines, press v first and move.
  • c on a line that has a note rewrites it. x deletes it.
  • Lines with a note carry a * in the margin.

Notes wait until you send them with s, or ctrl+a t from the workspace. You choose whether they go to the agent at once or through the queue. They go together, as one message:

Review notes:

api/auth.go:42-43
>         return nil
>     }
return an error here, the caller ignores nil

api/token.go:7
> +const ttl = 3600
make this a duration

If the agent is asking a question when you send them at once, they are queued instead, so they are not taken for the answer.

Queue

While an agent works you can line up what to tell it next. ctrl+a m asks for a message. You can edit the line with the arrows, ctrl+w, ctrl+u and the like. Messages wait in a panel under the changes and go to the agent one by one, each when it ends its turn. An idle agent gets the first at once. Nothing is sent while the agent waits for a permission, or after a turn that ended on an error.

In the queue panel (ctrl+a u):

KeyWhat it does
enterSend the next message now
pPause and resume. Pause when a turn ends with a question you want to answer first
a, e, xAdd, edit, delete a message
J, KMove a message down, up

Only Claude Code, Copilot CLI and Codex CLI say when their turn ends. Other agents keep a queue too, marked manual: each message is sent when you press enter in the panel.

Asking another session

ctrl+a k sends a message from the session on screen to another one. Pick the session, then choose:

ChoiceWhat it does
Send a messageQueues it there, as ctrl+a m would do from that session
Ask, and get the answer hereQueues the question there, shown as from <session>. What its agent says at the end of the turn the question starts is queued back for the session you asked from

When you ask, a second prompt takes what the session that asked should do with the answer. Leave it empty to only hand the answer over. That session receives one message:

I asked the session "api":
> What does GET /orders return when the cart is empty?

It answered:
> A 200 with an empty `items` array, never a 404.

Update the client to handle it.

Neither agent knows of the other: one gets a message, the other a message with an answer in it. Only Claude Code and Codex CLI can be asked, since they are the ones that tell what they said when a turn ends: for Copilot CLI the choice says not supported, and the other agents are only sent messages. Only the turn the question starts counts: if it ends on an error, if you interrupt it, or if the agent says nothing, no answer is sent back and the status bar says so. A question that was still being answered when cicoria closed is lost too.

Agents

An agent is a command line that cicoria runs in a terminal of its own. Five kinds are offered when you create a session:

  • Claude Code, always. It reports its status through hooks that cicoria registers for the process it launches, without touching your Claude Code settings. Its conversation continues when the session is reopened. The files it edits are highlighted in the tree.
  • GitHub Copilot CLI, always. It reports its status through the hooks of a plugin that cicoria loads for the process it launches, without touching your Copilot settings. It says nothing until the first message, so a new session reads idle once its screen is drawn. Its conversation continues when the session is reopened, and the files it edits are highlighted in the tree.
  • Codex CLI, always. It reports its status through hooks that cicoria passes on the command line of the process it launches, without touching your Codex settings. Codex asks you to trust them the first time: pick Trust all and continue, or it works but reports nothing. Like Copilot CLI it says nothing until the first message. Its conversation continues when the session is reopened, and the files it patches are highlighted in the tree.
  • Any command you add to the configuration. Its status is guessed from terminal activity.
  • A plain shell, always.

Configure

Settings live in ~/.config/cicoria/config.toml, or under $XDG_CONFIG_HOME when that is set. All are optional, and an unknown one is reported as an error.

SettingDefaultWhat it does
prefix"ctrl+a"The key that starts a command
default_agent"claude"The agent of the first session of a new workspace
notifytrueDesktop notification when a session not on screen needs input
left_paneltrueOpen with sessions and files shown
right_paneltrueOpen with changes and the queue shown
changes"uncommitted"What the changes panel opens on: what is not committed, or with "session" everything a session changed since it started
ignored_filestrueOpen with the files git ignores listed in the files panel, in grey. false leaves them out until i is pressed in the panel
close_on_exittrueClose a session when its agent or shell exits. false keeps it, marked ✕, to restart or close by hand
animationstrueA second of ASCII art when cicoria opens and quits and when a session is created or closed. Any key ends it
 
prefix = "ctrl+b"
right_panel = false

# Any command line can be an agent.
[agents.aider]
command = ["aider"]

# An entry named "claude", "copilot" or "codex" changes how Claude
# Code, Copilot CLI or Codex CLI is started, and one named "shell"
# which shell is run.
[agents.claude]
command = ["claude", "--model", "opus"]

# cicoria adds its own options at the end, so a launcher that
# passes the rest on ends with "--".
[agents.copilot]
command = ["ollama", "launch", "copilot", "--model", "gemma4:cloud", "--"]

[agents.codex]
command = ["ollama", "launch", "codex", "--model", "gemma4:cloud", "--"]

What is remembered

For each directory you open cicoria on, it keeps the sessions with their names, directories, starting commits, notes and queues. They are stored under $XDG_STATE_HOME/cicoria, or ~/.local/state/cicoria.

Agents stop when cicoria closes: each is told that its terminal is gone, as when a terminal window is closed, and killed only if it is still there two seconds later. The next time, every session is started again; Claude Code, Copilot CLI and Codex CLI pick up their conversation. Queues come back paused, so that opening cicoria never sends a message by itself.

A session belongs to the workspace it was created in, wherever it works: one created from ~/src/app to work in ~/src/lib comes back when cicoria is opened on ~/src/app, not on ~/src/lib. ctrl+a w lists the other saved workspaces, with the sessions of theirs that work in this directory and whether another cicoria has them open, and opens the one you pick in place of this one. A workspace that another cicoria has open is asked about before it is opened a second time, from there or with cicoria itself: its agents would run twice, on the same conversations. When cicoria is opened on a directory with nothing saved, the status bar says where the other sessions are.

Develop

git clone https://github.com/henomis/cicoria
cd cicoria
make build      # build ./cicoria
make check      # formatting, vet and tests: run it before a commit
make lint       # golangci-lint, as the CI runs it
make test-real  # the test that drives the real Claude Code; needs a folder it already trusts
make site       # serve the website in web/ on http://localhost:8000
make help       # every target

The end-to-end tests in e2e_test.go run the built binary in a terminal against a scripted agent. Bugs and ideas go to the issue tracker.

Cicoria is Italian for chicory. One grows in the agent pane each time you start. The idea turned up at 5:15 one October morning; the name came later that morning, from the chicory its author was cooking while an agent wrote the first version. Only the agent said when it needed attention.
